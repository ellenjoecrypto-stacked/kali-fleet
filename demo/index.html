Kali Fleet

An Empire PC Agent build for the Nebius x NVIDIA Hackathon — a plain-English security copilot for Kali Linux that can only ever touch the owner's own machines and authorized labs.

What it does

You type a request in plain English — "what's listening on this machine right now?" — and the fleet turns it into one allow-listed, read-only security check, runs it (or shows you the exact command first), and explains the result. Built for a repair-shop operator and home-lab owner who needs a security helper that physically cannot wander onto anyone else's network.

The loop

1 · RequestPlain-English request in
→
2 · NemotronIntent parsed via Nebius Token Factory — Nano class for parsing, Super class for narration, Ultra class reserved for deep log correlation. In the current build this step runs in labeled MOCK mode — no Token Factory key is set yet; the client wiring is real, the inference is not.
→
3 · Allow-list gateAction must be on the allow-list; scan targets must be in fleet_targets.txt
→
4 · ActionRead-only check runs — dry-run by default
→
5 · Audit logEvery attempt — allowed, refused, dry-run, executed — appended to a JSONL audit trail

The safety model

  • Allow-list only. Five read-only actions exist: sysinfo, listening ports, interface inventory, log triage, and an nmap service scan. Anything else is refused — there is no generic shell.
  • Own gear only. Scans run solely against targets in fleet_targets.txt (default: localhost). A request to scan anything else is refused and logged.
  • No payloads in this build. No exploit payloads, no credential attacks, no brute forcing ship here. Two exploit-class recon tools are registered in the codebase but carry no binaries in this build and cannot execute without the Boss's signed, single-use, per-run approval token.
  • Dry-run by default. The bot prints the command it would run; execution needs an explicit switch.
  • Kill switch. FLEET_STOP=1 or a STOP.txt file refuses every action instantly.
